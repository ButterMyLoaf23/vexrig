# VexRig MVP Planning Reflection

The hardest feature to make testable was probably the compatibility checker because there are a lot of different things that can make PC parts incompatible. I had to narrow it down to a few rules like CPU socket, RAM type, motherboard/case form factor, and power so the feature would be realistic to finish. AI also gave me ideas that could have made the project much bigger, like build recommendations, 3D PC visualization, FPS estimates, and live price tracking. I decided to cut those from the MVP because they would take attention away from the main goal of actually building and saving a PC. The dependency that affected the order the most was the build feature, because price calculation, compatibility checking, and saving builds all depend on having a working build first. Authentication also needs to happen before saving builds because the website needs to know who owns each build. One implementation risk I noticed early was how the database should connect a build to multiple PC parts, so I planned to use a separate relationship between builds and components instead of trying to store everything in one field. Overall, breaking the project into these smaller features makes it feel much more realistic to build one piece at a time.
